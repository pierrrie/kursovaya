# АРМ стоматолога (курсовой проект)

Курсовой проект по дисциплине **«МДК 05.03 Тестирование информационных систем»**.  
Тема: **«Создание и тестирование АРМ стоматолога»**.

Проект автоматизирует работу стоматологической клиники:
- управление пациентами;
- запись на прием;
- ведение визитов и результатов осмотра;
- документы стоматолога (направления, выписки, медкарта 043/у, наряды);
- роли пользователей: администратор, менеджер, стоматолог.

---

## Структура проекта

- `fastapi_app/` — REST API
  - `main.py` — точка входа API и регистрация роутов
  - `app/api/` — эндпоинты (`auth`, `patients`, `appointments`, `visits`, `dentist`, `admin`, `documents`, `mkb-s3`, `referrals`, `works`, `research`, `prescriptions`, `teeth`)
  - `stomatologiya.db` — локальная БД API
- `mysite/` — Django web-приложение
  - `frontend/views.py` — UI-логика и интеграция с API
  - `frontend/urls.py` — маршруты web-интерфейса
  - `frontend/templates/` — шаблоны страниц
  - `selenium_e2e_tests.py` — end-to-end UI тесты

---

## Функционал по ролям

### Администратор
- создание пользователей;
- доступ к странице МКБ-С-3 (загрузка JSON/DLL, reload состояния);
- общий доступ к реестрам.

### Менеджер
- добавление/редактирование/удаление пациентов;
- запись пациентов на прием;
- просмотр и фильтрация пациентов/визитов по датам.

### Стоматолог
- работа в «Дневнике врача»;
- ведение визитов (жалобы, анамнез, диагноз, результаты осмотра, примечания);
- направления на исследования/консультации;
- выписка из медкарты;
- медкарта стоматологического больного (043/у), экспорт Word/Excel;
- наряды на выполнение работ (материалы, зубная формула, трудозатраты, стоимость).

## Быстрый запуск (Windows / PowerShell)

> Запускать из корня проекта: `C:\Users\admin\Desktop\курсовая`

### 1) FastAPI

```powershell
cd fastapi_app
$env:PYTHONIOENCODING='utf-8'
& ".\venv\Scripts\python.exe" main.py
```

Доступно:
- API: `http://127.0.0.1:8000`
- Swagger: `http://127.0.0.1:8000/docs`
- Health: `http://127.0.0.1:8000/health`

### 2) Django

В отдельном терминале:

```powershell
cd mysite
python manage.py runserver 127.0.0.1:8001 --noreload
```

Доступно:
- Web UI: `http://127.0.0.1:8001`
- Login: `http://127.0.0.1:8001/login/`

## Тестирование

## Selenium E2E (основной набор UI-тестов)

Файл: `mysite/selenium_e2e_tests.py`

Запуск:

```powershell
cd mysite
python selenium_e2e_tests.py
```

Опционально headless:

```powershell
$env:E2E_HEADLESS='1'
python selenium_e2e_tests.py
```

Настраиваемые переменные окружения:
- `E2E_BASE_URL` (по умолчанию `http://127.0.0.1:8001/`)
- `E2E_FASTAPI_HEALTH_URL` (по умолчанию `http://127.0.0.1:8000/health`)
- `E2E_WAIT_SECONDS` (по умолчанию `10`)
- `E2E_HEADLESS` (`0`/`1`)

Покрытие набора:
- публичные и защищенные страницы;
- авторизация/выход;
- маршруты и ограничения по ролям;
- формы CRUD (пациенты, записи, визиты);
- сценарии стоматолога (дневник, документы, направления, наряды);
- редактирование приема/визита через дневник.

## Типовые проблемы и решения

- **`SessionNotCreatedException` в Selenium / Chrome не стартует**
  - обновить Chrome;
  - обновить `selenium`;
  - закрыть зависшие `chrome/chromedriver` процессы;
  - проверить запуск в `headless`.

- **Unicode ошибка в FastAPI при старте в Windows**
  - запускать с `PYTHONIOENCODING=utf-8` (см. команду выше).

- **Порт занят (`8000`/`8001`)**
  - проверить `netstat -ano | findstr :8000` и `:8001`;
  - освободить порт или запускать на свободном.

- **E2E тесты уходят в `skipped`**
  - в БД нет нужных тестовых пользователей/данных;
  - проверить актуальность логинов и ролей в тестовой среде.
